# SGB64 vs SGX
SGX files do not support loading of IMB instance meshes or VHF templates/hierarchies. SGB64 files are implied to be able to load these files, providing instancing and the capability of "templating" pre-made resources. 
1. This initially seemed beneficial as then SGB64-using tracks might be able to load the premade base game content like 3D trees, LOD-prepared trackside objects, and other instance-supported meshes and templates. However, this isn't actually that plausible because these premade entities would have to be extracted from the stock BFFs and repacked into new BFFs to be usable; the game can't "cross-load" BFFs from different tracks; all entities used on a specific track have to be packed into its BFF files. This is also likely why the game is ~130GB and growing; identical entities (textures, meshes, etc.) have to be packed multiple times across separate BFFs to be loadable across those tracks. There is no realistic way to "dedupe" these entities across their separate BFFs, due directly to the lack of cross-loading.
2. SGXs are still disadvantageous because they're not what the game is designed to load for production tracks. A consequence of this is that if an SGX is used as a track scenegraph, the game attempts to locate each referenced MEB's referenced MTX file on disk regardless of if a prepared BMT is present in the virtual hierarchy in the packed BFF. The raw MTX MUST be present, otherwise the materials will not load fully in-game. Additionally, each texture referenced by the MTXs MUST be present on-disk in addition to being present in the main track BFF, otherwise the game will hang when loading the track.
